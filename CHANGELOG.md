# v0.1.8 — адрес только из env, локальный listen по умолчанию

* `listen` удалён из `config.json`: адрес задаётся переменной `ZEN_BRIDGE_LISTEN`, по умолчанию `127.0.0.1:18788`. Старые конфиги с `listen` отклоняются strict-парсером.
* В Docker Compose контейнер слушает `0.0.0.0:18788` через `ZEN_BRIDGE_LISTEN`, а host-порт задаётся `BRIDGE_PORT` (по умолчанию `18788`).
* CI-сборка использует `-buildvcs=false`, чтобы `go build` не падал на VCS status в GitHub Actions.
* GHCR-образ теперь публикуется автоматически на каждый push в `main` (теги `latest` и SHA коммита), а также по тегам `v*`. Проверка и публикация объединены в один workflow: образ собирается только после успешного теста.
* Docker Compose использует готовый образ `ghcr.io/revellison/zen-bridge-go:latest`; README описывает установку из GHCR и альтернативную сборку из клона репозитория.

# v0.1.7 — без thinking_levels и лишнего списка моделей

* `thinking_levels`, `thinking_levels_url`, `thinking_levels_provider` и `thinking_levels_refresh_seconds` удалены полностью вместе с кодом загрузки models.dev, вариантами `model#level` и инъекцией `reasoning_effort`. Клиент передаёт параметры reasoning сам, шлюз их не трогает.
* Из `config.json` и `config.example.json` удалён общий список `models`: он дублировал `base_models` и больше не влияет на маршрутизацию. `/readyz` теперь проверяет наличие включённого аккаунта, а не списка моделей.
* `config.json` восстановлен после ошибочного усечения при редактировании: `client_token` и upstream-ключ извлечены из памяти работающего процесса и сверены по ID аккаунта.

# v0.1.6 — прозрачная труба без лимитов и валидации

* Удалены все ограничения запросов: `max_concurrent`, `max_queue`, `queue_timeout_seconds`, `request_timeout_seconds`, `response_header_timeout_seconds`, `max_body_bytes`, `max_response_bytes`, `max_sse_event_bytes`, `cooldown_seconds`, `defaults.max_concurrent` и `force_stream`. Старые `config.json` с этими полями отклоняются strict-парсером — удалите их.
* Сервер стал raw-passthrough: тело читается без лимита, JSON не валидируется по схеме, SSE не разбирается и не агрегируется, upstream-статус, заголовки и тело (включая ошибки) возвращаются клиенту как есть. `stream` передаётся в том виде, в котором его прислал клиент; повторов и преобразования ошибок больше нет.
* Неизвестная модель больше не блокируется: выбирается аккаунт, где она заявлена, иначе любой включённый. Cooldown, слоты, очередь и `AccountStatus` удалены; `internal/sse` удалён.
* HTTP-сервер больше не задаёт `ReadTimeout`, `ReadHeaderTimeout`, `IdleTimeout` и `MaxHeaderBytes`; compose не задаёт CPU/memory limits.
* Убраны искусственные ограничения конфигурации: размер файла, число аккаунтов, моделей и уровней мышления, длины ID и метаданных. Остались проверки корректности (дубликаты, пустые строки, auth, `allowed_hosts`).
* Ошибки конфигурации теперь называют проблемный блок: например, `invalid defaults settings: json: unknown field "force_stream"`.

# v0.1.5 — структура пакетов, Docker-only сборка, чистка

* **`internal/` разложен по пакетам:** `config` (типы и загрузка конфигурации), `accounts` (пул и cooldown), `upstream` (транспорт, профили, ID, `Retry-After`), `catalog` (discovery и кэш), `sse` (потоковая обработка), `server` (HTTP-роутинг и автокаталог). Публичные имена сокращены: `catalog.Report`, `catalog.Apply`, `catalog.Run`, `catalog.Options`, `upstream.ParseRetryAfter`.
* **Удалена prebuilt-схема:** `bin/`, `SHA256SUMS`, `Dockerfile.prebuilt`, `docker-compose.source.yaml` и `LIVE_TESTS.md` больше не нужны. Compose собирает образ напрямую из `Dockerfile`; бинарники нигде не хранятся.
* Тесты разложены по пакетам и сокращены; config-тесты переписаны без дублирования. `syscall.Flock` остаётся только для Linux — проект собирается и запускается исключительно через Docker.
* **`log_level` в config.json:** `debug`, `info`, `warn` или `error` (по умолчанию `info`), применяется к JSON-логам сервера после рестарта.
* **Уровни мышления (`thinking_levels`):** `"auto"` загружает индивидуальные уровни моделей из models.dev (`thinking_levels_url`, `thinking_levels_provider`, период `thinking_levels_refresh_seconds`), явный массив задаёт общий набор, `"off"` или отсутствие поля отключают функцию. Уровни публикуются в `/v1/models` как `model#level`; выбор такого ID отправляет upstream `reasoning_effort` (Chat) или `reasoning.effort` (Responses), если клиент не передал своё значение. Уровень из `#`-суффикса попадает в лог `upstream response`.
* README сокращён: как работает, быстрый старт, базовые и продвинутые настройки, API, модели, профили. Убраны локальная сборка, исторические диагностические разделы и ссылки на удалённые файлы.

# v0.1.4 — config.json в корне, force_stream, свой client_token без токен-файла

* **config.json в корне репозитория.** Файл `config/config.json` перенесён в `./config.json`, пример — в `./config.example.json`; каталог `config/` больше не используется. Дефолтный путь флага `--config` — `config.json` (текущий каталог). Путь `catalog_file` в шаблонах относительный (`data/...`): в контейнере разрешается в `/data/...` (том), локально — в `./data/...`. Compose монтирует корень репозитория в `/config` только для чтения — каталог, а не отдельный файл, чтобы атомарное переименование оставалось видимым при hot reload.
* **`force_stream` — гарантированный upstream-стриминг.** `"force_stream": true` (в шаблоне включён) заставляет шлюз запрашивать у upstream SSE для любого профиля (`raw`, `opencode-v1`, `opencode-v2`), не только `zen-free-compat`. Заголовки upstream приходят с первым чанком, а не после полной генерации, — исчезает «долгое молчание» в начале у нестриминговых профилей. Формат ответа клиенту не меняется: `stream: true` — поток сразу, `stream: false` — один собранный JSON.
* **Свой локальный ключ доступа только в config.json.** Поле `"client_token"` теперь обязательное и задаёт локальный Bearer-ключ (8–256 символов без пробелов). Автогенерация файла токена и команда `token` удалены целиком: ключ пишется прямо в config.json и используется клиентами как есть. Изменение значения действует после рестарта. Поле сделано приватным внутри конфига: сериализация `Config` секрет не раскрывает.
* **WORKDIR `/` в Dockerfile** (штатный WORKDIR distroless `nonroot` — `/home/nonroot`, из-за чего относительный `data/...` путь разрешался в read-only rootfs и давал EACCES от пользователя 10001). Ошибки кэш-каталога теперь печатают errno-причину. Prebuilt-бинарники `bin/` пересобраны (v0.1.4), SHA256SUMS обновлены.
* Сообщения `/readyz` и `model_unavailable` ссылаются на `config.json`. CI использует `docker-compose.yaml`/`docker-compose.source.yaml` по именам файлов репозитория и копирует `config.example.json` в корень.
* README переработан: быстрые старты, таблицы полей, отдельный раздел про стриминг и диагностику «долгого первого ответа» (очередь, cooldown, нестриминговый клиент, фоновые проверки).
* **Диагностика стриминга в логах.** Строка `upstream response` теперь содержит `model`, `account`, `client_stream`, `upstream_sse`; завершение потока — `upstream stream finished` с `first_byte_ms`, `events`, `error`, а агрегация — `upstream response aggregated`. По логам видно, просил ли клиент поток и стримил ли upstream, без догадок.

# v0.1.3 — один config.json

Все пользовательские настройки теперь находятся в `config/config.json`: параметры сервера, `models`, `defaults`, `api_keys`. Отдельный `accounts.json` не нужен. Файл-пример `config.example.json` предназначен только для первоначального копирования; приложение его не читает.

Поля ключей, моделей и общие параметры аккаунтов перечитываются без перезапуска. Параметры самого сервера (порт, лимиты, таймауты и политика upstream) требуют перезапуска. Старый внешний `accounts_file` поддерживается отдельно для совместимости, но его нельзя смешивать с inline-настройками.

`config.json` теперь содержит секреты: он исключён из Git и контекста Docker-сборки. Не публикуйте его. Именованный Docker-том хранит рабочий token и кэш, это данные сервиса, а не дополнительный файл для ручной настройки.

Для обновления перенесите свой список ключей и настройки в новый единый файл, затем выполните `docker compose up -d --build`. Не заменяйте рабочий файл пустым примером и не удаляйте именованный том. ZIP содержит пустой список ключей. Docker и внешний Zen в этой серии не тестировались.

# v0.1.2 — общие настройки и список ключей

Основной `config/accounts.json` теперь содержит три блока:

- `models`: модели для всех ключей.
- `defaults`: настройки транспорта, конкуренции и discovery один раз.
- `api_keys`: строки ключей; каждый ключ автоматически становится активным аккаунтом.

Пустой `api_keys: []` безопасно запускает сервис без upstream-аккаунтов. После добавления собственных ключей не нужно задавать `id` или повторять `enabled`. Изменение списка и общих настроек подхватывается горячей перезагрузкой.

Старый `accounts` поддерживается для индивидуальных настроек; `defaults` применяется только к простому списку `api_keys`. Не дублируйте один ключ в обоих форматах. Идентификаторы простых аккаунтов стабильны при перестановке ключей и не содержат ключ целиком.

При обновлении сохраните свои ключи и именованный том. После замены файлов выполните `docker compose up -d --build`. Не используйте `down -v`. Внешний Zen повторно не проверялся; Docker в среде подготовки недоступен.

# v0.1.1 — общие модели и профиль для IDE

- В `config/accounts.json` добавлен корневой `models`: общий список маршрутов для ключей без собственного списка.
- `accounts[].models` отсутствует или `null`: наследовать общий список; `[]`: не наследовать, оставить только discovery; непустой список: заменить общий.
- Старые файлы с индивидуальными списками поддерживаются. Изменения accounts.json подхватываются без рестарта; ошибочный файл не заменяет последнюю рабочую конфигурацию.
- Основной пример сохраняет реальные инструменты IDE и не добавляет фиктивные `bash`/`read` (`inject_compat_tools: false`).
- В примере полный таймаут увеличен до 300 секунд, заголовки до 90 секунд, тело запроса до 4 MiB. Это ограниченные исходные значения, не универсальная гарантия для любого контекста IDE.
- Нативные Chat Completions и Responses выбираются URL запроса. `stream: true` передаёт SSE по мере получения, `false` возвращает JSON. У `zen-free-compat` upstream остаётся потоковым, а JSON собирается только при запросе клиента.
- Автообновление каталога включено, фоновые генерационные проверки по умолчанию выключены (`discovery.check_enabled: false`). Их можно явно включить или запустить вручную.
- Диагностический 403 не удаляет ручные маршруты и предыдущую успешную проверку: запрос настоящей IDE может иметь другую форму. Проверка прекращает текущую серию после 401/403.
- Нет скрытого переключения профиля, ключа на public или повтора начавшейся генерации.

## Обновление

Сохраните рабочие ключи и настройки вне архива. Перенесите общий список в свой accounts.json, удалите индивидуальные списки только у ключей, которые должны его наследовать. Не заменяйте рабочие ключи шаблонным CHANGE_ME.

После замены кода/бинарников выполните `docker compose up -d --build`. Простого hot reload достаточно только для изменения accounts.json; новые бинарники и config.json требуют перезапуска/пересоздания контейнера. Именованный том с локальным токеном и кэшем нужно сохранить: не выполняйте `docker compose down -v`.

Новые проверки этой версии локальные; внешний Zen повторно не тестировался. Исторические результаты и ограничения находятся в LIVE_TESTS.md. Docker в среде подготовки недоступен.
